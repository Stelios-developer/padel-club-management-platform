# Ανεξάρτητη φόρτωση στο web

Το web φορτώνει ταυτόχρονα προφίλ, γήπεδα, κρατήσεις, συνδρομές, προγράμματα και ειδοποιήσεις. Για διαχειριστές φορτώνει επιπλέον μέλη και ιστορικό εισόδου. Κάθε ολοκλήρωση ενημερώνει τη σχετική ενότητα, χωρίς να περιμένει τις υπόλοιπες. Η αποτυχία του `/api/members/me` δεν εμποδίζει πλέον την αποστολή των άλλων αιτημάτων.

Κάθε ενότητα διακρίνει μη φορτωμένα δεδομένα, φόρτωση, επιτυχία με πραγματικά κενή λίστα και αποτυχία. Η αποτυχία εμφανίζει τοπικό μήνυμα και κουμπί επανάληψης για **ένα** endpoint. Η γενική ανανέωση παραμένει διαθέσιμη. Οι μετρητές χωρίς επιτυχημένη απόκριση εμφανίζουν `—`, όχι μηδέν ή ανενεργή συνδρομή.

Σε αποτυχημένη ανανέωση παραμένει η προηγούμενη επιτυχημένη εικόνα, με ώρα τελευταίας ενημέρωσης και σαφή προειδοποίηση ότι δεν επιβεβαιώθηκε ξανά. Οι ενέργειες που εξαρτώνται από αυτά τα στοιχεία περιμένουν επιτυχημένη επαναφόρτωση. Οι επιχειρησιακοί έλεγχοι του backend εξακολουθούν να ισχύουν.

Το `resources.js` κρατά snapshots μόνο στη μνήμη. Αποσύνδεση, αλλαγή ρόλου στην επίδειξη και HTTP 401 καθαρίζουν τα προστατευμένα δεδομένα. HTTP 403/404 διαγράφουν το προηγούμενο snapshot της συγκεκριμένης ενότητας. Τα aborts και οι εκδόσεις αιτημάτων αποτρέπουν την εμφάνιση καθυστερημένων αποτελεσμάτων άλλου λογαριασμού, παλαιότερης ανανέωσης ή άλλης σελίδας μελών. Μόνο πραγματικό HTTP 404 προφίλ ανοίγει onboarding.

## Αναμονή και εγγραφές

Τα API αιτήματα έχουν συνολικό όριο **15 δευτερολέπτων**, που περιλαμβάνει ανάκτηση token και ανάγνωση του response body. Η ανανέωση token έχει επίσης όριο 15 δευτερολέπτων. Η επανάληψη είναι ρητή επιλογή χρήστη· δεν γίνεται αυτόματη επανάληψη POST, PUT, PATCH ή DELETE. Timeout εγγραφής προειδοποιεί ότι η ενέργεια μπορεί ήδη να έχει καταχωριστεί. Οι δημιουργίες κράτησης/συνδρομής διατηρούν την προστασία idempotency που περιγράφεται στο [API contract](API.md#idempotency-contract).

Ο κωδικός κράτησης στη reception διατηρείται κατά την ανανέωση άλλων δεδομένων. Η απόκριση ελέγχου εισόδου εμφανίζεται πριν από την επαναφόρτωση του ιστορικού. Αποτυχία ιστορικού δεν αντικαθιστά μια ολοκληρωμένη απόκριση ελέγχου. Αποτυχία του ίδιου του ελέγχου εμφανίζεται μέσα στη φόρμα, με κουμπί επανάληψης και χωρίς να εμφανίζεται επιτρεπόμενη είσοδος. Οι διαθέσιμες ώρες και οι συνδρομές συγκεκριμένου μέλους έχουν επίσης τοπική επανάληψη στα dialogs.

## Έλεγχοι

```powershell
npm --prefix web run check
npm --prefix web test
```

Στις 01/10/2026 πέρασαν **26 frontend tests**, περιλαμβανομένων 15 νέων ελέγχων για timeout, ακύρωση, διατήρηση snapshot, στοχευμένο retry, ανεξάρτητη φόρτωση, αλλαγή λογαριασμού/σελίδας και 401/403/404. Τα tests αναμονής χρησιμοποιούν μικρό όριο και ελεγχόμενες αποκρίσεις.

Στο πραγματικό `padel-e2e`, μέσω Nginx/Gateway και πραγματικού Keycloak, ελέγχθηκαν:

- Διακοπή `notification-service`: οι 100 ήδη φορτωμένες ειδοποιήσεις παρέμειναν με προειδοποίηση· dashboard, γήπεδα, πρόγραμμα και αναζήτηση διαθέσιμων ωρών συνέχισαν να λειτουργούν.
- Νέα σύνδεση με την ίδια υπηρεσία εκτός λειτουργίας: φορτώθηκαν τα υγιή τμήματα, ενώ οι ειδοποιήσεις εμφάνισαν μόνο σφάλμα και retry, χωρίς ψευδή ένδειξη κενής λίστας.
- Επαναφορά ειδοποιήσεων: το τοπικό retry φόρτωσε τη λίστα και αφαίρεσε το σφάλμα.
- Διακοπή `member-service`, τόσο σε ανανέωση όσο και σε νέα σύνδεση: γήπεδα και πρόγραμμα παρέμειναν ορατά. Τα εξαρτώμενα προφίλ/μέλη/προσωπικές συνδρομές εμφάνισαν δικά τους σφάλματα· οι νέες κρατήσεις περίμεναν ενημερωμένα στοιχεία. Δεν άνοιξε λανθασμένα onboarding.
- Διακοπή `access-service`: το ιστορικό παρέμεινε με σήμανση, ο έλεγχος εμφάνισε τοπικό σφάλμα και δυνατότητα επανάληψης. Επανάληψη ιστορικού διατήρησε τον κωδικό και το μήνυμα της φόρμας.
- Επαναφορά `access-service`: η επανάληψη με τον ίδιο κωδικό ολοκληρώθηκε, εμφάνισε την πραγματική απόκριση `OUTSIDE_BOOKING_WINDOW` (η δοκιμαστική κράτηση είναι αργότερα μέσα στην ημέρα) και ανανέωσε το ιστορικό με την καταγραφή. Δεν έγινε αλλαγή κράτησης ή καταχώριση πληρωμής.

Στιγμιότυπα: [λειτουργικό dashboard κατά τη διακοπή](screenshots/failure-isolation-dashboard.png), [παλιότερες ειδοποιήσεις με σήμανση](screenshots/failure-isolation-stale.png), [διακοπή προφίλ](screenshots/failure-isolation-profile.png), [σφάλμα ελέγχου εισόδου](screenshots/failure-isolation-access.png).

Μετά τους ελέγχους επανήλθαν και τα **13 containers**. Όσα έχουν healthcheck ήταν `healthy`. Το τελικό [dashboard μετά την επαναφορά](screenshots/failure-isolation-recovered.png) φορτώθηκε με πραγματική σύνδεση, ενεργό κουμπί νέας κράτησης και χωρίς errors. Ο έλεγχος `nginx -t` πέρασε. Διορθώθηκε επίσης η διατήρηση παλιότερων assets στον browser: τα static αρχεία επανελέγχονται μετά από deployment, με νέα URLs για τα ενημερωμένα αρχικά αρχεία. Τα modules εφαρμογής/API χρησιμοποιούν το ίδιο auth module ώστε να μοιράζονται τα tokens στη μνήμη.

Οι διακοπές αφορούν το τοπικό δοκιμαστικό stack. Δεν έγινε deployment σε εξωτερική εγκατάσταση. Η ανεξάρτητη εμφάνιση στο web δεν καταργεί τις πραγματικές εξαρτήσεις των backend υπηρεσιών· για παράδειγμα, ο έλεγχος εισόδου εξακολουθεί να χρειάζεται στοιχεία κράτησης, μέλους και συνδρομής.
